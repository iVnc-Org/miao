## 故障结论

目标设备是 x86_64 OpenWrt 24.10.0，使用定制内核 `6.12.16` 和 fw3/iptables legacy。TUN 可用，但 nftables Netlink 查询返回 `EINVAL`。原配置强制 `auto_redirect: true`，因此 sing-box 已创建 TUN、启动 SOCKS 监听后，仍会在 post-start 阶段退出。

当前项目原本已有 OpenWrt 包管理器与模块准备代码。源头项目 `/data/projects/iVnc-Org/miao-offical` 已将依赖检查放入共享的内核启动函数，但 Linux 配置仍强制启用 `auto_redirect`，并安装 `kmod-tun`、`kmod-nft-queue`。直接移植这部分代码不能解决目标设备缺少 nftables 的问题。

设备的软件源对应官方 `6.6.73` 内核，与运行内核不匹配。此次利用已有 TUN 运行兼容策略路由，没有在设备安装模块、强制忽略依赖或修改持久防火墙配置。

## 审查发现与处理

| 问题 | 最终处理 | 验证证据 |
| --- | --- | --- |
| 强制 nftables，无法运行于当前 fw3 固件 | 按实际 Netlink 能力解析 `auto`、`nftables`、`policy_route`；仅明确不支持规则时允许自动回退一次 | Linux 增强模式、真机兼容模式均通过；强制增强模式在真机正确报错 |
| 网页启动等入口遗漏依赖准备 | 网页、自动恢复、CLI、模式切换和 VPS 激活衔接共享准备及生命周期校验 | 首次网页启动、缓存恢复、模式切换验收通过 |
| 软件包记录可能与实际能力、内核 ABI 不符 | 优先检查设备与权限；只按需准备 TUN；安装前核对 ABI，给外部命令设置超时 | 包状态、ABI 拒绝及命令超时测试通过 |
| 进程存在或监听一度出现就被视为成功 | 同时检查本次核心启动完成日志、持续存活、控制接口、SOCKS、TUN 与策略路由；即时读取两路日志并限制缓存大小 | 原报错不再误报成功；隔离数据面与异常退出检查通过 |
| 策略切换后，兼容模式的规则可能覆盖原始 bypass 意图 | 从用户配置重新生成路由动作，再应用实际接管策略；bypass 明确指定 direct 后备 | 增强/兼容模式下的进程黑白名单及切换回归通过 |
| 停止请求被订阅或依赖 I/O 阻塞，旧任务可能重新启动代理 | 操作编号使旧任务失效；分离配置和进程生命周期锁；取消不打断包数据库事务 | 慢订阅期间停止在 2 秒内完成；前端并发请求测试通过 |
| fw3 转发阻断或重载清空规则 | 自动发现可信 LAN，仅管理本实例 INPUT/FORWARD 规则；周期修复链内容和跳转 | 真机及 Linux 模拟 fw3 的 LAN 流量、清空链后恢复通过 |
| 强制退出遗留策略规则、nftables 表或随机表中的本地路由 | 记录准确增量、表句柄及进程身份；清理并恢复自有资源；拒绝接管未知现存资源 | 两种策略下核心 SIGKILL、Miao SIGKILL、重启及冲突保护通过 |
| Miao 被强制结束后，改以代理池启动仍残留 fw3 链 | 即使不创建 TUN，也先回收旧实例的规则；清理失败返回诊断 | 新增回归先复现失败，修复后 Linux 与真机均通过 |
| 策略读取失败被当成空规则，可能记录错误归属 | 无法读取时拒绝建立或更新归属记录 | 新增失败读取回归通过；未知规则保护验收通过 |
| 实际 SOCKS 节点接受 UDP ASSOCIATE，但远端 UDP DNS 没有回包 | 远端 DNS 改用 TCP；生成配置、缓存和旧运行配置同步迁移；直连 DNS 保持 UDP | 同一节点 TCP DNS 成功、UDP 超时；修复后 Cloudflare 的系统 DNS 与透明访问成功 |
| 旧缓存可能重新引入不兼容接管方式 | 缓存结构升至 10，指纹包含 TUN 与核心修订；运行清单绑定配置 SHA256、核心修订和操作编号 | 旧运行配置纠正、策略迁移、运行状态恢复通过 |

运行目录权限为 0700；新 `/api/tun` 使用已有认证与 CSRF 保护。内嵌 sing-box 保持 `1.14.4` 和固定源码修订，没有为此次修复升级核心版本。
