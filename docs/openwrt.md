# OpenWrt 接管方式与故障排查

[文档目录](README.md) · [配置与代理模式](configuration.md)

Miao 支持 amd64、arm64 的 OpenWrt。全局和进程模式需要可用的 `/dev/net/tun` 与 `CAP_NET_ADMIN`；代理池模式只提供 SOCKS 端口，不需要 TUN 或 nftables。

安装时使用对应架构的 Linux release 产物，其 Rust 程序使用 musl，内嵌 sing-box 关闭 CGO。自行构建时同样需要 musl 目标与静态内核；普通发行版上的 glibc 构建不能直接代替 OpenWrt 产物。

## 自动适配流量接管

启动服务即可使用，接管方式由 Miao 自动配置。网页只显示适配进度与运行状态，具体实现和回退原因放在只读的“网络诊断”中。

Miao 查询当前进程可用的内核能力，优先使用 nftables 防火墙接管；明确缺少支持时使用策略路由。检测不依赖 `nft` 命令是否安装，也不单凭固件名称或软件包记录判断。基础查询通过但核心启动所需规则明确不受支持时，先清理失败实例，再自动回退一次。

旧配置或旧客户端提交的 `tun.routing: nftables`、`policy_route` 在加载时自动迁移为自适应，原有节点、分流规则和可信 LAN 设置继续使用。加载过程保留原用户文件，后续保存采用规范配置；新配置无需填写接管策略。`/api/tun` 保留 GET/PUT 管理可信 LAN，返回的 `routing: auto` 是只读兼容字段；仅提交旧接管字段时保持现有 LAN 配置和运行实例。`/api/status` 的 `runtime` 提供实际方式及准备、启动、就绪、失败状态。

自定义 LAN 区域才需要填写可信设备名；默认从 UCI 的 lan 区域与 ubus 发现：

```yaml
tun:
  lan_interfaces: [br-lan]
```

原生 nftables 接管通过 sing-box 自带的出站标记防止循环，出站连接遵循系统路由。因此经 Tailscale、其他 VPN 或不同网卡到达的节点可以使用其实际出口，避免将所有连接强制绑定到 WAN。显式设置的节点 `bind_interface` 与 `detour` 保持有效。代理池不接管系统流量，同样无需绑定默认网卡。

旧内核自动使用的策略路由仍需默认网卡绑定来防止循环。如果节点需要经其他 VPN 网卡到达，可在节点 JSON 中明确指定对应的 `bind_interface`。接管能力检测和节点出口配置分别决定内核适配与连接路径。

开发排障可用环境变量 `DISABLE_NFTABLES=true` 模拟缺少 nftables 的环境；日常使用不需要设置。Miao 显式控制 sing-box 子进程环境，使实际运行方式与检测结果一致。

配置错误、权限不足、端口冲突、探测超时和节点失联分别报告；节点连通性不决定接管策略。失败实例清理不完整时报告错误，保留归属记录供恢复。

本次运行已确认缺少规则能力后，后续配置更新继续使用策略路由，避免反复失败。下一次点击“启动服务”或重启 Miao 时自动重新检测，适应模块或软件包变化。

## 自动接入 DNS

全局模式启动时，Miao 自动发现 procd 管理的 dnsmasq，在确认代理 DNS 的 TCP/UDP 可用后，将其公网查询接入回环端口 `127.0.0.1:6263`。dnsmasq 继续处理 DHCP 主机名、本地域名和反向查询，Tailscale 的 `*.ts.net` 私有域继续交给 MagicDNS，保留 A 与 ULA AAAA；仅对该私有域放行重绑定保护。公网 DNS 经当前代理节点使用 TCP 查询，节点域名使用独立的引导解析，避免依赖循环。

接入使用有效 conf-dir 中的临时片段，不写 UCI、DHCP、Wi-Fi 或 `/etc/resolv.conf`。系统默认解析器指向 Tailscale 等非回环地址时，还会用独立的运行时 nft 表将其 IPv4/IPv6、UDP/TCP 查询送入 dnsmasq，避免绕过保护；核心引导解析和 Tailscale 基础连接保持独立。通过服务管理器重启对应 dnsmasq 实例以加载片段并清除旧缓存，DNS 转发验证通过后才显示启动就绪。启动期间固件重新生成 DNS 配置时，会完整复检一次，避免采用过期设置。停止或切换代理池时先撤销 DNS，再停核心；恢复失败时保留核心并报告错误。procd 独立监督的恢复守护在管理器或核心异常死亡后恢复 DNS；管理器死亡时，确认核心退出后也会清理本实例遗留的网络资源。网络诊断显示 DNS 接入或恢复结果，无需选择 DNS 模式。

当前自动适配支持一个活动 dnsmasq 实例、标准端口 53，以及一个位于 `/tmp` 的 conf-dir。已有显式公网上游、公共域名专用上游、DNSSEC 或不支持的配置结构会在中断现有服务前报告冲突，避免两个上游竞争；其他 DNS 服务需要单独适配。非回环系统解析器的补充保护需要 nft 工具和相应内核能力；预检不支持时明确拒绝，系统解析器已指向回环 dnsmasq 的常规配置不需要额外 DNS 表。进程模式维持原有 `dns_follow_process` 语义，代理池不接管系统 DNS。

Google 解析曾被旧上游污染时，路由器缓存会在接入时清除；终端自己的缓存需等待过期或重连 Wi-Fi。验收应使用默认 DNS 访问 Google 首页、跳转及搜索页面，出口 IP 变化或单个 gstatic 探针成功不能代替这一检查。

## fw3 与进程代理

ImmortalWrt 等固件可能同时提供 `fw3`、`fw4`，其中 `fw3` 是指向 `fw4` 的兼容链接。Miao 比对实际文件身份，避免将这种系统误判为旧 fw3；原生 fw4/nftables 系统不因此要求安装 iptables。真正独立的旧 fw3 程序仍使用下面的规则管理方式。

fw3 环境会在运行期间管理带本实例标记的 INPUT/FORWARD 规则链，允许可信 LAN 与当前 TUN 必需的转发和回包。可信 LAN 默认来自名为 `lan` 的 UCI 防火墙区域；自定义区域请填写 `tun.lan_interfaces`。设备名必须存在，且不能是回环或 TUN 本身。

Miao 每秒检查自己的规则，防火墙重载或规则链被清空后自动补齐；重载期间可能短暂影响经过代理的连接。停止服务、启动失败和内核退出会清理自有规则；下次启动也会清理该运行目录留下的规则。全局模式的独立 DNS 守护在管理器死亡后也会回收自有网络资源；没有 DNS 守护的模式在下次启动时清理，包括改以代理池模式重启的情况。清理失败会报告诊断，不会显示为成功停止。

运行目录的 `network-ownership.json` 记录本次新增的策略规则、nftables 表句柄和进程/启动/网络命名空间身份，用于强制退出后的恢复。启用 TUN 时需要可执行且能成功查询策略规则的 `ip` 命令；无法读取规则时拒绝建立资源归属。已有但没有本实例归属记录的 TUN、策略优先级或 `inet sing-box` 表会引发冲突提示，避免覆盖其他代理。一个网络命名空间只运行一个透明代理实例；嵌入部署须为实例提供独立运行目录。

部分 BusyBox `ip` 无法查询或删除编号大于 255 的路由表，还可能将大编号显示为非数字名称。Miao 通过 Netlink 记录原始规则及完整 32 位表号，并直接清理内核中匹配的自有资源；已不存在的表和规则视为完成清理。旧运行记录只在归属可唯一匹配时迁移。

进程名单适用于路由器本机进程。兼容策略将黑名单的 `bypass` 生成为明确的 direct 出站；增强策略的 bypass 也带 direct 后备，避免缺少预匹配能力时规则被跳过。自定义 bypass 规则保留明确指定的出站，未指定时使用 direct 后备。

路由器的 dnsmasq 可能代其他进程发起 DNS，进程 DNS 归属仍受系统行为限制。当前生成的透明代理配置面向 IPv4；IPv6 不属于这次兼容修复的接管范围。

远端 DNS 通过当前代理使用 TCP，本机和 LAN 仍可通过 UDP 或 TCP 发起 DNS。这样不依赖上游 SOCKS/HTTP 节点的 UDP 转发能力，也能兼容接受 UDP ASSOCIATE 却不回传 DNS 的节点。节点本身的普通 UDP 转发能力仍由上游服务决定；更换 DNS 传输不能为节点补充该能力。直连的本地 DNS 保留 UDP。

## 依赖与缓存

所有实际启用 TUN 的入口都先准备设备与权限。已有 TUN 可以直接使用，不要求找到 apk/opkg；缺少设备时先尝试加载模块，再在 OpenWrt 上安装必要的 `kmod-tun`。增强队列模块不再是兼容模式的启动前提。

安装前核对固件内核依赖，更新索引、检查和安装均有超时，并串行执行。取消启动会停止等待，不会直接中断正在写入包数据库的后台安装事务。安装超时后需检查实际包和模块状态再重试。

例如部分固件标为 OpenWrt 24.10.0，但使用定制的 6.12 内核，而配置的软件源属于官方 6.6 内核。此时应使用固件匹配的软件源；自动策略通常可以直接选择兼容接管。软件包显示已安装，也不代表模块已加载或内核能力可用。

旧版本生成配置缓存会因结构版本或策略不同而重新生成，继续复用本地节点缓存，不主动刷新订阅。运行配置旁的 `routing.json` 绑定配置 SHA256、内核修订与操作编号，防止过期配置被另一个启动任务复用。

## 常见错误

| 错误或现象 | 处理方向 |
| --- | --- |
| `missing nftables support: ... invalid argument` | 旧防火墙或定制内核缺少能力，新版本会自动改用策略路由；若仍失败，查看诊断中的清理或回退错误 |
| `NO_NET_ADMIN` | root 运行，或给容器提供网络管理权限与 TUN 设备 |
| `TUN_UNAVAILABLE` / `TUN_LOAD_FAILED` | 检查设备映射、模块是否与运行内核匹配 |
| `KERNEL_ABI_MISMATCH` | 换用当前固件匹配的软件源和模块 |
| `FW3_LAN_UNDETECTED` | 用真实可信 LAN 设备填写 `tun.lan_interfaces` |
| `FW3_IPTABLES_MISSING` | 先检查是否运行旧版本误判了 `fw3 -> fw4`；真正的旧 fw3 才需要其 iptables 用户态工具 |
| `ROUTING_INSPECTION_FAILED` | 检查 `ip -4 rule show` 是否可执行且成功返回 |
| `FW3_CLEANUP_FAILED` | 检查本实例规则链的引用、iptables 权限和锁竞争 |
| `DEPENDENCY_TIMEOUT` | 检查软件源及安装状态；面板仍可查看状态或取消启动 |
| `START_CANCELLED` | 本次操作已被停止或更新请求取代 |
| `DNS_PORT_CONFLICT` | 6263 是自动 DNS 保留端口，检查面板、SOCKS 或其他服务占用 |
| `DNS_POLICY_CONFLICT` / `DNS_CONFIG_UNSUPPORTED` | 现有 DNS 上游或服务结构超出自动适配范围，按诊断检查冲突 |
| `DNS_OWNERSHIP_CONFLICT` | 本实例 DNS 片段被外部修改；保留外部内容，检查修改后重试停止 |
| `DNS_SERVICE_FAILED` | dnsmasq 接入或恢复失败，查看服务日志；仍存活的核心会保留以供恢复 |
| `READY_TIMEOUT` | 查看内核启动日志、监听端口、TUN 与路由是否就绪 |
| 本机代理可用但 LAN 不通 | 检查可信 LAN、网关设置、转发与防火墙规则 |
| 原上游 SOCKS 可用，但 Miao SOCKS 和透明访问均超时 | 检查节点是否经 Tailscale 等非默认出口到达；更新后原生 nftables 接管会遵循系统路由，避免错误绑定 WAN |

启动成功要求子进程持续存活、本次内核发布完成启动日志、控制接口和 SOCKS 可用，以及 TUN/策略路由满足当前策略。公网可达性通过独立的连通性测试确认。
